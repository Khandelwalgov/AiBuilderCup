Deployment preparation only; no cloud resources have been provisioned.

API: build the Cloud Run target with `docker build --platform linux/amd64 -t opportunity-api apps/api` (or use Cloud Build on an amd64 builder). A native `docker build -t opportunity-api apps/api` is sufficient for local testing on your host architecture. The container binds Cloud Run's PORT, runs unprivileged, and does not run migrations on startup. Run Alembic once as an explicit release job before traffic. Supply DATABASE_URL (Cloud SQL PostgreSQL via a configured connector/socket or private network), CORS_ORIGINS (JSON list with the Hosting origin), and FIREBASE_PROJECT_ID. Use Cloud Run Application Default Credentials with the minimum Firebase Authentication permission needed for revocation checks. Store passwords in Secret Manager, never in the image.

Web: configure apps/web/.env.local with VITE_API_BASE_URL pointing to the HTTPS Cloud Run API and the four Firebase web configuration values. Build using `make contracts` then `cd apps/web && pnpm build`. `firebase deploy --config infra/firebase.json --project YOUR_PROJECT --only hosting` deploys the static bundle after you have selected and configured your own project. No default paid project or resource creation is automated.

Before production: confirm database backups, IAM, HTTPS, retention/export/deletion implementation, quota/budget alerts, Firebase authorised domains, and tested authentication. Synthetic seeding is an explicit development command and must not be run against production. Cloud Scheduler, GCS uploads, and Gemini are not part of Phase 1.
