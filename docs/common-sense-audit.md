The exact graduate/nonstudent combination is valid. The reproducible defect was retained active study-mode and school-recognition answers which were hidden by conditional questions, yet blocked the whole form. The old generic conflict text made the valid degree answer appear responsible.

## Reproduction and failure classification

A fictional legacy profile was seeded directly into a **random isolated PostgreSQL schema**, with student=false, legacy education=undergraduate, mode=full_time and school-recognized=true. An official Firebase Auth emulator account opened the actual frontend, authenticated through the actual FastAPI verifier and loaded those rows. The baseline browser test saw No and Undergraduate, no mode control, a generic conflict notice, and disabled Save. It passed as a reproduction (`/tmp/common-baseline.log`, 1 test, 4.2 seconds). No production authentication override or real-user mutation was used.

The emulator seed deliberately represents this ambiguity.

## Issues found and fixes

1. Hidden legacy dependent answers + generic rejection. Show precise field/value/active-period explanations in EN/HI; retain unchanged broken legacy details as visible warnings; reject new/changed genuine contradictions. End-date only with consent, preserve values/history, and support explicitly archiving the ambiguous legacy answer. Unsaved corrections are cleared only after confirmation and are not assigned invented history dates.
2. Conflated course/attainment. Add `current_education_level` and `highest_completed_education`; keep `education_level` unchanged as ambiguous legacy data. Do not infer either new fact. Completed education is an optional section/source follow-up; not every education interest triggers every question.
3. Temporal source meaning. Current-course/mode checks depend on contemporaneous enrollment; current school recognition needs a school-level current course. Explicit No is a substantive failure for a source that explicitly requires current study; absent/expired/conflicting enrollment is unknown. Historical study never establishes current enrollment. Old ambiguous source-rule mappings remain unknown pending admin review.
4. Income scope order. Previously different periods/definitions could conflict before filtering. Select exact scope/period first, then detect conflicting applicable amounts. Zero remains known; missing scope remains unknown, not invalid income or guessed household sum. Verified income-certificate facts now also match explicitly required period/definition rather than being reused across incompatible scopes.
5. Nationality representation. `IN` could fail a source saying Indian. Normalize supported Indian aliases for comparison, preserve stored/source text, and treat legacy Other as unspecified. Plain-language nationality input replaces the underspecified Other picker. Supported Hindi/English names in the demo geography also compare consistently without mixing location dimensions; unmapped cross-language spellings stay unknown. This is representation handling, not a new nationality law or complete nationality/geography ontology.
6. All conditions not applicable. A fresh assessment with only renewal-specific conditions could become potential_match. It now stays uncertain when no applicable condition has actually been assessed. Competitive selection/approval disclaimers remain.
7. Personal/business meaning. New changed business facts cannot be submitted to a person/dependent. Business registration geography and current activity are independently optional; legal structure defaults to unknown rather than silently unregistered. Existing business operating geography retains its scoped meaning. Business edits merge existing fact metadata instead of dropping validity dates.
8. Save recovery. Semantic issues, invalid values/dates, stale revision, unavailable subject/session, network/database and document storage failure have distinct codes/messages. Current question errors are highlighted. Profile and workspace reloads require a deliberate discard choice; answers are preserved until then. Existing verified facts stay outside user-edit replacement.
9. Historical display. Archived mode/school/course no longer appear as present-day answers. They remain in a separate dated history section, with previous-period labels. Age shows its recorded date when available, never a fabricated DOB. Explicit age as-of comparisons cannot silently reuse a different undated recorded age.
10. Bundle freshness and fallback robustness. Hosted HTML/assets are configured to revalidate (not deployed). A new age-date display initially exposed missing context in a legacy mocked response; the production UI now handles absent metadata without crashing. The original browser contract remains intact.

## Full-flow semantic sanity pass

Public discovery and location filters still do not create domicile facts. Personal/dependent/household/business permissions are resolved server-side; active membership/guardianship dates and consent revocation remain checked. Adults are not granted access by kinship. Income is never derived by summing household members. Document possession, stored file, expiry, verification, linked suitability and task progress remain independent; file replacement/deletion/token revocation tests still pass. Fresh/renewal is explicit. Missing facts remain unknown, actual disqualifiers remain restrictions after unrelated uploads, and selection/procedure/interpretation is not guaranteed entitlement. Assistant explanations remain cited deterministic results; no new model call was made. Administrator ingestion permission, review/corrections and publication remain unchanged and guarded.

The detailed [44-scenario matrix and fact inventory](domain-semantics-matrix.md) records valid/invalid/ambiguous combinations, periods, clarification and test locations. Some complexity remains unmodeled rather than being guessed: multiple simultaneous courses, parallel editable income scopes, DOB-based aging, global nationality aliases, authoritative document verification and adult invitation/export/erasure workflows. Production uploads remain gated.

## Data and architecture boundaries

No automatic conversion of saved legacy education; no edits to either genuine DEPwD draft, its 70 citations, source snapshots or review history. New fact keys use the existing text/JSON fact storage, so no destructive or DDL migration is required. API/TypeScript contracts regenerated. Evaluator fingerprint version advances to 4 and includes implicit enrollment dependencies; historical evaluation records remain immutable. Extractor guidance uses explicit current/completed keys for future candidate generation; provider defaults/fallback policy are unchanged. No new extraction, official publication, paid AI, deployment or cloud provisioning.
