## Local preparation and handoff contract

Prepared selection is `processing/import-manifest-v1.json`, version `prepared-import-v1`. Each entry binds snapshot/source hash, component path/file hash, stable focus, idempotency hash and `deterministic_valid_human_review_required`. Allowed component paths are only `processing/codex-v1/<snapshot>[.<component>].candidate.json`; duplicate focuses/paths, hash changes, source mismatch, traversal and claimed approval are refused. Candidate files are limited to 2 MiB each / 16 MiB total / 20 components per source. All original-page citations are revalidated during production dry-run. Without a selection manifest the legacy single-file path remains compatible. Original text, OCR, independent-verifier and human-publication contracts are preserved.

`infra/corpus_job.py --all-batches --record-count N` uses the exact checksum-validated handoff record count, no fixed 125-record truncation. The processing scope is reviewed before the operator supplies N. `--state-name current` selects the initial ledger; `--state-name rajasthan-supplement-20261017` selects the separately approved three-record supplement. Strict state names cannot escape the existing private checkpoint prefix. Sidecars and OCR remain unverified evidence unless explicitly reconciled; they cannot silently become original captured text or public policy.

The ignored public release config uses runtime secret version 2 and migration mode `upgrade`. After the human approval, the operator derives the actual SQL role from that pinned secret in memory and invokes:
