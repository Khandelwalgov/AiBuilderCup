# 0001 — A truthful public discovery foundation

Phase 1 implements PostgreSQL-backed public discovery, not eligibility or real-source ingestion. The only protected resource is `/v1/me`, returning the verified caller's Firebase identity; it accepts no target user ID. No private domain tables are reachable through public endpoints. Later person, household, business, and document routes require object-level authorization before exposure. Kinship and household membership confer no permissions. Token checks use the Firebase Admin SDK with revocation checking; there is no authentication bypass or emulator mode.

The domain schema separates User and Person, supports dated household membership and relationships, explicit consent revocation, unrestricted business legal status, and exactly one subject per fact/document/evaluation/action. ProfileFact.context will carry scheme-specific income definitions, periods, and sources. Null values remain unknown; this phase has no evaluator. ApplicationRecord, ingestion runs, notifications and audit workflows will be added with their first real use rather than as unused tables now.

Opportunity identity is stable; numbered versions are append-only by future service policy. This foundation does not expose writes or enforce immutability with database triggers. Source status is independent of opportunity status. A source failure never deletes a version. Public browsing currently selects the latest version, including clearly unverified records; Phase 2 must select the last published version while candidates remain in an administrator-only review queue before ingestion is activated. Verification requires a URL, reviewer, and timestamp at the database boundary. Synthetic fixtures are immutable examples, without official URLs, amounts, deadlines, or requirements.

Country/state/district columns are discovery facets, not eligibility. The version's applicability and Requirement.rule fields support typed geography dimensions including domicile, residence, business registration, school and study location. Validated candidate-rule schemas and deterministic evaluation are Phase 2 work; no arbitrary expressions are executed.

UUID keyset cursors give stable ordering without offsets. Facet counts describe this database, not national programme coverage. Schema is generated from SQLAlchemy via a committed Alembic migration; OpenAPI is exported from FastAPI, and openapi-typescript generates the client contracts used by openapi-fetch. EN/HI static UI strings are separate from source content; fixture descriptions remain English.

Privacy limitation: no sensitive-data capture, export, deletion, document parsing, or consent administration is implemented in Phase 1. Do not onboard real sensitive user information until those controls and permission tests exist.
