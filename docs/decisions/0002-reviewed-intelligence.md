# 0002 — Reviewed publication and deterministic personal assessment

Phase 2 preserves the monorepo, SQLAlchemy/Alembic, Firebase and generated contract boundary. `Opportunity.published_version_id` selects the public record; only a matching real, verified, published version is visible. Extraction creates drafts. Review uses row locks and an expected candidate hash; approval writes rules, evidence, reviewer/time and the pointer in one transaction. Older candidates cannot roll publication backward. Published versions cannot be edited through the service. Previous publications remain historical; they are not returned by the current catalogue. DB operators retain privileged write ability.

One adapter captures a fixed official guideline/amendment bundle. Hashes include both documents. Immutable text/page snapshots, per-document metadata and run records support reproducible citations. Repeated bytes reuse existing candidates; extraction failures can retry. Source failures affect freshness, not opportunity existence or approval. The official index is a reviewer completeness check, not a nationwide discovery feed. Manual execution is intentional; scheduling follows validated extraction.

Google GenAI receives only public source text, explicit untrusted-data framing and a schema, with no tools or automatic function calls. Pydantic rejects extra fields and unsafe rule shapes. Every nonempty metadata field requires a citation, and every cited passage must match the recorded URL/page after whitespace normalization. Later amendments must be accounted for by extraction and human review. Quote matching does not validate meaning or completeness. Missing credentials/results never trigger a synthetic fallback.

The typed rule language supports only allowlisted facts and comparisons, nested all/any, rule dates, income period/definition and document dependencies. Unsupported conditions remain unknown. Personal facts carry origin, verification and validity; conflicting/stale/future facts remain unknown. Domicile and residence use distinct keys. No family income aggregation occurs. Document self-reporting is not verification. The personal evaluator does not consume business/household facts; those subject contexts explicitly return unknown. Required document text also produces evidence-gap rows so metadata cannot silently disappear from an assessment.

Results persist a version ID, engine version, fact snapshot and evaluation timestamp. Stable condition hashes, document blocker identities and common fact keys are a functional preparation for shared actions. Group all/any semantics aggregate unknown correctly. The result is potential relevance or a preliminary blocker, never an authority's official decision or application readiness guarantee.

Firebase UID resolution creates a separate account identity. Only that account's Person is queried or mutated. API clients cannot set origin, verification or admin role. Profile writes replace self-reported facts while preserving verified evidence, and the UI clears private query state on account changes. Administrators are DB-role guarded; the first role comes from a privileged CLI that verifies the Firebase identity and audits the change. No public role-grant endpoint exists.

Privacy limits remain material: synthetic profile data only, no user-document ingestion, no real sensitive-data onboarding, no export/deletion or consent lifecycle UI yet. Review text is privileged; public pages expose reviewed policy evidence only. No private profile is sent to Gemini. Public source parsing runs synchronously within the backend and is not yet isolated in a separate job/container; inputs are allowlisted and bounded. Raw binary archival and durable crash recovery remain follow-up work.
