# Documentary dependencies and assessment identity

Published documentary requirements carry a nullable canonical dependency dictionary. Only deliberately enumerated plain document names/aliases normalize; conditional/unsupported names remain requirement-specific clarification actions. The authoritative URL/page forms the policy basis. Subject context and actual subject ownership scope actions. Unknown parental-income assessment definitions/periods are not inferred. Typed UDID evidence and equivalent document-list entries share the same dependency. Original descriptions, clauses and versioned requirement links are retained independently. Action progress never verifies evidence.

Migration d03e9c62e843 adds nullable document_dependency and indexed evaluation fingerprint columns without rewriting historical records or either genuine draft. New publications populate dependency metadata through the ordinary authorized review service. No real publication occurred in Finale.

Fingerprints contain subject kind/ID, published version ID, relevant canonical facts (value, origin, verification, validity and income definition/period), evaluation date, application context and engine version 3. Record UUIDs and audit-only recorded_at timestamps are excluded. Consecutive identical inputs reuse the previous immutable snapshot and evaluated_at. A meaningful transition or return to a prior context creates a new historical assessment; daily date changes allow date-dependent rules/expiry to be rechecked. The fingerprint is indexed, deliberately not globally unique, so historical reversions remain representable.
