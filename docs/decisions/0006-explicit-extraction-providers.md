The user explicitly authorized OpenAI for development to unblock official-source ingestion while retaining Gemini as primary. `AI_EXTRACTION_PROVIDER` is a closed `gemini|openai` setting, defaulting to Gemini. Selection happens once per ingestion; exceptions never trigger fallback. Each provider has separate backend credentials/model settings. Known cross-provider key formats are rejected before transmission. Existing public source adapters, Pydantic contracts, citation validation, deterministic evaluation, permissions and review/publication boundaries remain authoritative.

Providers return a candidate plus measured usage through a small protocol/result type. Gemini retains the official Google SDK. OpenAI uses the documented Responses REST interface with existing HTTPX, no new SDK/dependencies, no tools and `store=false`. Only the adapter's public official-source text is sent. OpenAI's wire schema recursively removes defaults, requires every object property and disallows extra properties; existing nullable unions remain nullable. The unchanged application models still validate lengths, rule shape, fact types and income contexts. A transport schema cannot replace semantic validation.

Migration `a70d81ea2f20` adds nullable provenance fields to runs/versions. Legacy provenance stays unknown rather than guessed. New records store provider/model/extractor identity, source hash, actual usage and sanitized failures. Credentials, raw provider error messages and private profiles are not captured.

Deduplication uses snapshot + provider + model + extractor version while the source remains unchanged. Switching providers can produce a new reviewed candidate, but returning to an already processed identity reuses it. A real source-content reversion still requires fresh review. A schema-scoped source lock serializes all providers against one stable opportunity identity. No provider may move the publication pointer; only authorized review does that.
